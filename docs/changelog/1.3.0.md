# 1.3.0 — 2026-10-03

## Added

- JSON Schema of the detector config, `schemas/detector_config.json`
  (JSON Schema 2020-12), generated from the Rust types and shipped in the
  npm package `@vitavision/chess-corners` under `schemas/`. Field
  descriptions come from the doc comments; numeric bounds are `minimum` /
  `maximum`, and pixel-valued fields carry `x-unit: "px"`. The schema
  describes the default feature set (no `ml-refiner` variant).
- `schemars` feature on `chess-corners-core` and `chess-corners`
  (`chess-corners/schemars` forwards to core): derives
  `schemars::JsonSchema` for `DetectorConfig` and every type reachable
  from it. The serde representation is unchanged.
- `cargo xtask emit-schemas [--check]` regenerates / verifies the
  committed schema; CI runs the `--check` form.
- WASM: `DetectorConfig.fromJson(json)` / `toJson()` and the free function
  `default_detector_config_json()` (alias `defaultDetectorConfigJson()`)
  read and write the config as JSON in the schema's shape, so a
  schema-driven form can edit a config and hand it to
  `ChessDetector.withConfig`. Invalid input throws an `Error` with a
  descriptive message. The typed class API is unchanged. The package grows
  by ~65 KB raw / ~28 KB gzipped for the JSON glue.

## Changed

- Config field doc comments now state units and valid ranges. The
  `MultiscaleConfig` / `UpscaleConfig` docs now show the unit variants as
  the plain strings serde emits (`"single_scale"`, `"disabled"`).
